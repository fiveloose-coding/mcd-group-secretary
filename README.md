# 🍟 麦麦拼单秘书 · mcd-group-secretary

> 基于 **麦当劳中国 MCP** 的团队拼单助手 —— 把「一群人各自想吃什么」变成一份**最省钱、账目清楚**的拼单方案。

---

## 一句话定位

办公室里 8 个人一起点麦当劳，有三件事每次都得靠人肉硬算：**谁想吃的对应菜单上哪个 SKU**、**怎么凑优惠最省**、**钱怎么分**。

「麦麦拼单秘书」把这三件事全部交给 **麦当劳中国 MCP** + 一套**确定性算法**完成：

- 找菜单、找优惠、算价格 —— 调麦当劳 MCP 拿**权威数据**，绝不自己猜；
- 对菜单、分账单、比方案 —— 用**纯函数**算，规则写死、可单测、**分账误差恒为 0**。

---

## 它解决什么真实问题

| 痛点 | 现状 | 本项目的做法 |
|---|---|---|
| **菜单对不上** | 群里说的是「麦辣鸡腿堡」，菜单上排的是「麦辣鸡腿堡套餐 三件套」 | 确定性文本匹配（精确 → 别名 → 包含 → 二元组相似度），并且**永远返回候选列表与置信度**，不做黑箱猜测 |
| **不知道有什么优惠** | 要一页页翻券、翻活动，还怕漏 | 主动拉取门店级促销规则、可用券、企业团餐助餐服务 |
| **价格不敢信** | 自己算容易错，满减怎么叠更说不清 | **价格一律以 MCP `calculate-price` 返回为准**，本项目绝不自算价格 |
| **分账算不清** | 共享一份薯条怎么摊？满减按什么比例分？ | 纯函数分摊算法，全程**整数「分」运算**，附不变量校验，**分摊误差恒为 0** |
| **下单有风险** | 群里一激动点错、超预算 | **默认只出方案、绝不下单**；下单动作被显式隔离在人工确认之后 |

## 核心能力

| 能力 | 实现方式 |
|---|---|
| 门店与场景探测 | MCP `query-nearby-stores`（到店自提）/ `delivery-query-stores`（外送） |
| 真实菜单获取 | MCP `query-meals`，支持到店自提 `orderType=1` 与外送 `orderType=2`，以及**企业团餐 `beType=6`** |
| 门店级优惠获取 | MCP `query-promotions`（满减/满折规则）、`query-store-coupons`（门店可用券）、`query-meal-assistance`（团餐助餐服务） |
| 权威计价 | MCP `calculate-price`（含优惠后的最终价，以服务端为准） |
| 账单精确分摊 | 纯函数 `splitBill()`，支持单品独占与多人共享，折扣按比例分摊 |
| 省钱方案比对 | 纯函数 `compareScenarios()`，对多个候选方案取最优并给出差额 |
| 拼单文本解析 | 纯函数 `parseOrderSheet()`，把群聊式的拼单文本解析成结构化订单 |

## 快速开始

### 1. 申请麦当劳 MCP Token

前往 [麦当劳 MCP Server](https://github.com/M-China/mcd-mcp-server) 说明页面，用手机号登录后点击右上角「控制台」→「激活」，一键复制 Token。

### 2. 配置 MCP

把 `mcp-config.example.json` 复制为 `mcp.json`，并将其中的 `${MCD_MCP_TOKEN}` 替换为你的真实 Token（**不要把真实 Token 提交到任何仓库**）：

```json
{
  "mcpServers": {
    "mcd-mcp": {
      "type": "streamablehttp",
      "url": "https://mcp.mcd.cn",
      "headers": {
        "Authorization": "Bearer ${MCD_MCP_TOKEN}"
      }
    }
  }
}
```

### 3. 跑起来（零依赖，只需 Node.js 18+）

```bash
# 自检：验通 Token、打印服务器信息与可用工具数
MCD_MCP_TOKEN=你的Token node src/group-secretary.mjs doctor

# 查该配送地址下的可用团餐门店
MCD_MCP_TOKEN=你的Token node src/group-secretary.mjs stores --address-id <配送地址ID>

# 生成拼单方案（企业团餐：beType=6 且 orderType=2）
MCD_MCP_TOKEN=你的Token node src/group-secretary.mjs plan \
  --address-id <配送地址ID> \
  --file examples/sample-order.txt \
  --date "2026-10-12 12:00" \
  --json out/plan-result.json
```

运行单元测试（纯函数层，无需 Token、不联网）：

```bash
node --test tests/*.test.mjs
```

### 实测约束（官方文档未写明，由实测发现）

1. **企业团餐场景 `calculate-price` 必须传 `gmServiceCode`**，否则返回 `600061 团餐助餐服务参数缺失`；
2. **团餐的订单类型固定为 `orderType=2`（外送）**，不能传到店自取用的 `orderType=1`；
3. **助餐服务档位会显著影响实付**：另一张商品原价 ¥477.50 的团餐单，GMS001 实付 ¥381.45、GMS003 实付 ¥453.08，**相差 ¥71.63** —— 这类差额只能实测得出，无法估算，这正是本项目要用 `calculate-price` 逐档比价的原因；
4. 店级券接口 `query-store-coupons` 在团餐场景可能返回空数组（本单门店即为空）。

## 设计原则（工程取舍）

### 1. 价格权威性：绝不自算价格

麦当劳的定价、满减、券叠加规则是**业务方权威**，任何在本地重写一遍的计算都必然与实际不一致。因此本项目把**所有价格计算都委托给 MCP `calculate-price`**，本地只负责「准备场景 → 调用 → 比较结果」。

### 2. 分摊确定性：整数分运算 + 不变量校验

钱的分摊是最容易出错、也最容易被忽视的地方。本项目：

- 全程使用**整数「分」**（`Math.round(元 * 100)` 只在解析入口发生一次）；
- 均分有余数时，按**参与者给定顺序**逐分分配，结果可复现；
- 折扣按各人小计**比例分摊**，同样使用确定性余数分配；
- 每次分摊后校验不变量 **Σ 个人应付 === 小计 − 折扣**，不成立即抛错。

### 3. 匹配可解释：不做黑箱猜测

菜名匹配采用显式优先级（精确 → 别名 → 包含 → 二元组相似度）与显式阈值。低于阈值**不猜**，而是标记为「待确认」并把候选列表一起返回，交给人工或上游 Agent 决策。

### 4. 默认不下单：风险动作显式隔离

`plan` 命令全程只读，不会产生任何订单。下单类工具（`create-order` / `party-order-create` / `mall-create-order`）**不在本项目的自动流程中**，需要人工确认后单独触发。

## 目标用户

- **企业行政 / 团建组织者**：给团队订企业团餐，需要一次算清总价与人均；
- **办公室「点单侠」**：常年负责收集口味、凑优惠、催收款；
- **宿舍 / 家庭多人点单场景**：需要把共享单品公平地摊开。
